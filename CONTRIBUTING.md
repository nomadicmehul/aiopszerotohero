# Contributing to AIOps Zero to Hero 🤝

This curriculum only stays alive if practitioners keep it current. The AI-ops stack changes monthly — **your contribution is not optional decoration; it's the maintenance model.**

## 🪜 The Contributor Track

Contribution is a learning path of its own. Climb it:

| Level | Who | What you do | How to get there |
|---|---|---|---|
| 🐣 **Learner** | Anyone using the curriculum | Open issues: broken links, confusing sections, resource suggestions | Just start — use the issue templates |
| 🛠️ **Contributor** | 1+ merged PR | Add resources, labs, job-profile teardowns, interview questions; fix and prune | Open your first PR (guide below) |
| 🔍 **Reviewer** | 5+ merged PRs, active in discussions | Vet suggested resources, review PRs for a stage, run quarterly link-freshness sweeps | Ask a maintainer; we'll add you to CODEOWNERS for a stage |
| 🧭 **Stage Maintainer** | Sustained ownership | Own a stage's roadmap: decide structure, merge PRs, keep it state-of-the-art | Nominated by maintainers after consistent reviewing |

Contributions count for your portfolio too — "maintainer of the Stage 6 (AI Reliability) curriculum" is a strong CV line for exactly the jobs this repo targets.

## ✅ What we accept

- **Resources** — courses, docs, talks, posts, tools that taught *you* something. Free-first; mark paid with 💰.
- **Hands-on labs** — exercises with clear outcomes; the best contribution possible.
- **Job-profile teardowns** — new postings decoded into stages ([career/job-profiles.md](career/job-profiles.md)); anonymize the company.
- **Interview questions** you were actually asked (anonymized).
- **Pruning** — removing stale/dead/superseded content is as valuable as adding.
- **Translations** — open an issue first to coordinate.
- **New sections/stages** — open a discussion issue before writing; the roadmap shape is deliberate.

## 🧪 The resource quality bar

Before adding a resource, all four must be true:

1. **You used it.** Not "looks good" — you did the course / read the doc / ran the tool.
2. **It's the best option you know** for that topic, or covers a gap.
3. **Primary or close to it.** Official docs > maintainer blog > practitioner write-up > listicle (rarely accepted).
4. **It's current.** For fast-moving topics (Stages 4–9): published/updated within ~18 months, or timeless (SRE book).

## 📝 How to PR

1. Fork → branch (`add-resource/stage-06-langfuse-course`)
2. One logical change per PR (one resource, one lab, one fix)
3. Follow the existing format of the file you're editing — resource lines look like:
   `- 🎓 [Name](url) (free) — one line on *why it's worth the time*`
   (🎓 course · 📖 docs/book/article · 🎥 video · 🧪 interactive lab · 💰 paid)
4. In the PR description: which quality-bar points it meets, and your one-line experience with it
5. A reviewer/maintainer for that stage reviews within a week

## 🏷️ Issue labels

`good first issue` · `broken link` · `resource suggestion` · `stale content` · `new lab` · `job profile` · `discussion`

## 🌡️ Freshness policy

Every stage gets a quarterly sweep (reviewers): dead links out, superseded tools flagged, dates checked. Each stage README may carry a `Last reviewed: YYYY-MM` line — update it when you sweep.

## 🚫 What we don't accept

Affiliate links, self-promotion without disclosure, AI-generated resource dumps nobody vetted, paid resources with free equivalents of equal quality, and tool ads disguised as tutorials.

## 📜 Ground rules

Be kind ([CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md)). Assume good faith. Beginners' confusion reports are premium contributions — they show us exactly where the curriculum fails.
